# Phase 5 — Deployment (Platform Decision & Direct Mode)

This covers taking the working local app live: choosing a free platform after
checking what "free" actually means in 2026, changing the frontend so it can
run on a host that only runs Streamlit, deploying it, and setting up repo and
secret hygiene. 

**Live app:** https://egyptian-labor-law-rag.streamlit.app/

## 1. Choosing a free platform

The project requirement was free hosting, decided at this phase. Each
candidate was checked against current official documentation rather than
assumed.

| Option | Finding | Outcome |
|---|---|---|
| Hugging Face Spaces (Docker) | The current docs state that Gradio and Docker Spaces "run on compute and require a paid plan to create" (PRO for personal accounts); only Static Spaces are free for everyone. | Rejected — not free. |
| Google Cloud Run | Has an always-free monthly allowance (2M requests, 180,000 vCPU-seconds, 360,000 GiB-seconds), but a billing account with a card on file is required. Scales to zero, so the first request after idle is a cold start. | Rejected — requires a payment method; the requirement was free hosting. |
| Free container tiers of roughly 512 MB RAM | The app loads PyTorch plus `multilingual-e5-base`; RAM need was estimated at roughly 1.5–2 GB (an estimate, not a measurement). | Rejected — would not fit without replacing the embedding stack, which was validated in Phase 1 and was not going to be swapped for a hosting constraint. |
| Streamlit Community Cloud | Free, no payment method. Builds the app directly from a GitHub repo using `requirements.txt`. | **Chosen.** |

**Known risk at decision time:** Streamlit Community Cloud's RAM cap could not
be verified from documentation. The only evidence found was that limits are
shared by all users, can change, and that apps loading large data into memory
have failed to start. The decision was to try it — it costs nothing, and
failure would not lose any work.

## 2. Making the app runnable on a Streamlit-only host

**Why a change was needed:** Streamlit Community Cloud runs only the Streamlit
script, while the Phase 4 frontend calls the FastAPI backend at
`localhost:8000` — which does not exist on that host.

**Approach: a `RAG_MODE` switch in `streamlit_app.py`.**

| Mode | Behavior |
|---|---|
| `api` (default) | Unchanged from Phase 4: the frontend calls the separate FastAPI backend at `API_URL`. Used for local development. |
| `direct` | The frontend runs `ask.py`'s pipeline inside the Streamlit process. Used on Streamlit Community Cloud. |

The mode is read from the `RAG_MODE` environment variable first, then from
Streamlit's Secrets, defaulting to `api`. Nothing about local development
changes unless the setting is present.

**How direct mode works:**

- **One-time load.** `_load_pipeline()` is wrapped in `st.cache_resource`, so
  the embedding model, Chroma collection, and Groq client are created once per
  server process and shared by every visitor and session.
- **Warm-up with a visible message.** In direct mode the page calls
  `_load_pipeline()` right after the masthead and disclaimer, under a
  "loading the system for the first time" spinner (Arabic and English), so the
  first visitor sees progress instead of a first question that hangs.
- **Cached answers.** `_answer_direct()` is wrapped in `st.cache_data`
  (500 entries) and keyed on the whitespace-normalized question — the same
  idea as the API's LRU cache. Exceptions are not cached.
- **Same error contract.** A Groq rate limit (`status_code == 429`) becomes the
  same localized warning as in API mode; any other failure is logged and shown
  as the generic localized error. The rendering code needed no changes.
- **Secrets.** The Groq key is read from the environment, falling back to
  `st.secrets["GROQ_API_KEY"]`, because the Groq client reads the environment.
- **Memory logging.** After loading, the app logs its peak memory
  (`[memory] peak RSS after loading pipeline: X MB`, Linux/macOS only) so the
  host's real RAM ceiling can be checked against measurement instead of the
  earlier estimate.

**Two host-compatibility measures, both defensive:**

- **CPU-only PyTorch.** `requirements.txt` adds
  `--extra-index-url https://download.pytorch.org/whl/cpu` and `torch`. The
  default Linux PyTorch wheel bundles CUDA libraries (multiple GB) that this
  app never uses; pip prefers the `+cpu` build from the extra index.
- **SQLite shim.** Some hosts ship a SQLite too old for Chroma. If
  `pysqlite3-binary` is installed (declared for Linux only), the app swaps it
  in for `sqlite3`; if it isn't, the app silently carries on. This was added as
  a precaution.

**Trade-off, stated plainly:** the deployed app does **not** run the FastAPI
layer built in Phase 4 — it calls the pipeline directly. This is a deliberate
deviation from the planned FastAPI + Streamlit architecture for the live
version only. The FastAPI backend and the two-process design remain in the repo
and remain the way to run the app locally.

## 3. Deployment

**Steps performed:**

1. Repo pushed to GitHub with `data/chroma/` committed (the app needs the
   persisted index at runtime) and `.env` excluded.
2. App created at share.streamlit.io: main file
   `src/frontend/streamlit_app.py`, Python 3.11 (matching the local
   environment).
3. Secrets set in the app's Advanced settings, entered as TOML (string values
   in plain straight double quotes): `GROQ_API_KEY = "..."` and
   `RAG_MODE = "direct"`.

**Result:** the app is deployed and answers questions on Streamlit Community
Cloud at https://egyptian-labor-law-rag.streamlit.app/.

**Expected operational behavior of a free host** (general to free hosting,
not measured for this app): an idle app may be put to sleep and need to
reload the model on the next visit, and the in-process answer cache resets
whenever the app restarts.

## 4. Repo and secret hygiene

A `.gitignore` excludes `.env`, virtual environments, caches, and editor/OS
files. The Groq API key lives only in the platform's Secrets (or a local `.env`
during development), never in the repo.
